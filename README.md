# B站学梗 / Bilibili Meme Learner

让麦麦（MaiBot）**从 B站 视频里自己学梗**，并**理解群友分享的视频**。

她不再只会看标题 —— 会读字幕、看弹幕爆发点、翻热评，把「这个梗是什么意思、怎么用、什么来历、敏不敏感」整理成结构化资料，写进自己的黑话库，聊天时自然用上。

> 零第三方依赖 · 纯标准库 · 本地模型抽取 · 无云端费用

## ⚙️ 配置

复制 `config.example.toml` 为 `config.toml`（**不要提交 config.toml 到仓库**）。也可以在 WebUI 的插件配置里改。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `write_to_db` | `true` | `false` = 只预览不写库（试玩模式） |
| `reject_taboo_strong` | `true` | 拒绝高敏感梗入库 |
| `sessdata` | `""` | **B站 SESSDATA，有它才能拿字幕**（见下节） |
| `max_candidates` | `5` | 同名多视频时比较几个候选 |
| `comment_pages` | `2` | 每视频抓几页热评（每页 20 条） |
| `danmaku_segments` | `2` | 最少抓几个弹幕分片（长视频会自动增加） |
| `rate_limit_seconds` | `1.2` | B站 请求间隔，太小会被风控 |
| `llm_task` | `utils` | 用哪个模型任务抽取（`utils` / `learner`） |
| `min_confidence` | `0.35` | 低于此置信度不入库 |

## 🔑 关于 `sessdata`（重要）

### 为什么需要

B站 把**字幕**和**评论区 AI 总结**都锁在登录后面。未登录时接口返回：

```json
{"need_login_subtitle": true, "subtitles": []}
```

所以想让它理解 40 分钟的技术视频，**必须配 `sessdata`**（字幕是讲解正文的唯一可靠来源）。

### 怎么拿（扫码，不用 F12）

用仓库里的助手脚本，**全程扫码，不需要复制任何东西**：

```bash
# 宿主机上（需要 python3 + qrcode）
pip install "qrcode[pil]"
python3 tools/bili_login.py --config /实际路径/config.toml
# → 生成二维码图片，扫码 + 手机确认后自动抓 SESSDATA 并写进 plugin config.toml
```

它会：

1. 调 B站 官方 `passport-login/web/qrcode/generate` 生成二维码
2. 轮询 `qrcode/poll`，你扫码 + 手机确认后拿到 `SESSDATA`
3. 写入指定的本地配置文件；容器部署时请指定映射到宿主机的配置路径

### 安全提示

- **用小号**，不要用主号
- cookie 等同于该账号的登录凭证，别泄露、别提交进仓库（`.gitignore` 已包含 `config.toml`）
- 插件只在**收到视频时**才请求，不批量爬；限速 1.2 秒
- SESSDATA 几个月会过期，失效后插件自动降级（回复里会注明"字幕：需登录 cookie"）

### 没有 cookie 会怎样

不会崩，会**自动降级**：

- `/学梗` 只能用标题 + 弹幕 + 评论推断 → 置信度会被压低，可能不入库
- `/总结视频` 只能用标题 + 弹幕 + 评论 → 提示词强制把 `reliability` 压到 0.4 以下，并说明"未获取到字幕"

## 🧠 工作原理

```
        ┌─────────── /学梗 ───────────┐
关键词 → 多查询合并 → 候选视频 → 逐个体检
                              ├─ 热门评论 → 元信号打分（"讲得全面"/"瞎讲"）
                              └─ 字幕探测 → 有字幕 +3.0 分（能拿到"来历"）
                                    ↓ 选最优
      标题 / 简介 / 标签 / 字幕正文 / 弹幕爆发点 / 热评
                                    ↓ 本地模型结构化抽取
      {content, aliases, origin, meaning, usage, examples, taboo, freshness, confidence}
                                    ↓
                jargons 表（麦麦原生黑话库）
                                    ↓
                聊天命中关键词 → 自动注入 → 自然用梗
```

```
        ┌────────── /总结视频 ────────┐
链接/BV →（短链展开）→ 视频信息 → 字幕(优先) + 弹幕爆发点 + 热评
                                    ↓ 本地模型一次吃下
                一句话结论 + 带时间戳的要点 + 适合谁 + 值得看吗
```

### 几个设计决策

**1. 弹幕按时间轴聚类，不是简单堆叠**

弹幕带 `progress` 毫秒时间戳。按 10 秒窗口统计密度找**爆发点** —— 那是观众觉得精彩的位置。只把爆发点里带信息的弹幕（过滤"哈哈哈/666/前方高能"）喂给模型，既省 token 又拿到语境。

弹幕分片数按时长自适应（每片约 6 分钟，最多 8 片），避免长视频只取到开头。

**2. 选源打分**

```
score = 0.6·ln(弹幕数) + 0.25·ln(播放量)
      + 2.0（标题含"什么梗/梗指南"）
      + 0.35·(评论正信号数) − 0.8·(评论负信号数)
      + 3.0（有≥20条字幕，仅对前3名探测）
```

正信号：`讲得全面 / 起源 / 捋清楚 / 课代表 / 省流 / 科普 / 谢谢`
负信号：`瞎讲 / 不对 / 胡说 / 误导 / 编的`

**3. 写进麦麦自己的黑话库**

产出直接写 `Jargon` 表（`is_global=1`、`is_complete=1`、`created_by=AI`），复用麦麦原生的黑话注入机制 —— 不改框架，它就像"自己学的"。

**4. 去重**

入库前按 `content` 查重，同名梗走 update 而不是 create。

**5. 弹幕 protobuf 手写解析**

容器里没有 `google.protobuf`，所以自己写了 20 行 varint 解析器解 `DanmakuElem`（字段 2 = 时间戳，字段 7 = 内容）。零依赖。

## ❓ FAQ

**Q：提示"没搜到相关视频"**
长查询容易被 B站 搜索返回 0 条（例如 `"XX 是什么梗"`）。插件已自动尝试三种查询组合。仍然失败时直接用 BV 号。

**Q：提示"触发风控(-352)"**
请求太密。等几分钟，或把 `rate_limit_seconds` 调到 2.0。

**Q：学了但麦麦不用**
梗需要在实际聊天语境里被命中才会注入。另外新梗 `count` 从 0 开始，用得越多越容易被选中。

**Q：`/梗库` 里看不到刚学的**
检查 `write_to_db` 是否为 `true`，以及回复里是否写了"已写入黑话库"。

**Q：字幕一直是"需登录 cookie"**
`sessdata` 没配或已过期。重跑 `python3 tools/bili_login.py --config /实际路径/config.toml` 扫一次码。

**Q：会不会把奇怪的梗学进库**
有三道关：`taboo strong` 拒收、`min_confidence` 门槛、敏感度原因会记录在回复里。另外 `write_to_db=false` 可以先只用预览模式观察。
